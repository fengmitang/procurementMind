# 审批风险调查与程序审查契约 v0.1

> 日期：2026-08-05  
> 状态：DEV-07A 确定性阶段；真实模型语义审查和制度证据待接入

## 1. 执行顺序

风险调查使用统一聊天入口。执行顺序固定为：

1. `get_requirement_risk_signals` 必须首先执行。
2. 风险信号失败时立即停止，不猜测风险。
3. 读取 `get_purchase_request`，确定设备和供应商上下文。
4. 在工具预算内并行执行：
   - `query_purchase_analytics`：历史价格和采购统计。
   - `get_supplier_performance`：履约、延期和数量异常比例。
   - `get_similar_cases`：可解释相似案例。
5. RAG 材料未提供时，制度证据记录为 `UNAVAILABLE`。
6. 生成结构化摘要并执行程序 Reviewer。

Agent、MCP 和模型均不直接访问 MySQL 或 Redis。后端继续负责身份、权限、数据范围、风险规则、
数值和记录编号。

## 2. 风险摘要字段

每个 `summary_items` 项包含：

- 风险代码、类型、等级和后端规则是否命中。
- 原始事实、指标、相关记录编号和规则阈值。
- 数据来源。
- 明确标记为待核实的可能原因。
- 信息是否完整、信息缺口和人工核实项。

摘要不能输出批准、驳回或供应商最终选择。未命中风险只表示固定规则未命中，不代表审批结论。

## 3. 证据状态

`evidence` 使用三种状态：

- `SUCCESS`：工具返回经过后端校验的数据。
- `FAILED`：工具调用失败，保留错误码和原因。
- `UNAVAILABLE`：能力或材料尚不可用，或工具预算不足。

部分证据失败时保留其他成功结果，并将 `complete=false`。当前真实制度材料未提供，因此风险调查
不会被描述为完整。

## 4. 程序 Reviewer

程序 Reviewer 将每条摘要与原始 `risk-signals` 逐字段核对：

- 风险代码、类型、等级和命中状态。
- 事实、指标、阈值和相关记录编号。
- 是否引用后端风险来源。
- 是否出现批准、建议通过、驳回等越权文字。

程序 Reviewer 不替代真实模型语义审查。后续语义 Reviewer 负责检查遗漏、编造、推测强度和
表达质量，但不能覆盖程序校验结果。

## 5. 评测

基础风险评测定义位于 `tests/fixtures/risk_evaluation_v0.1.json`，指标包括：

- 风险召回和漏检。
- 错误风险和精确率。
- 证据覆盖率。
- 审批越权次数。
- 程序审查是否通过。

真实模型和制度材料接入后，将在相同结构上补充语义审查和制度证据评测，不改变风险摘要契约。
