# Procurement Agent 后端接口联调说明

更新时间：2026-07-30

本文面向需要接入采购后端的前端、外部 Agent、身份网关、通知网关及其他业务模块
开发人员，说明各模块与当前后端之间的边界、认证方式、接口用途、调用顺序和错误
处理要求。

字段级请求和响应结构以当前服务生成的 OpenAPI 为准：

- Swagger UI：`GET /docs`
- OpenAPI JSON：`GET /openapi.json`

当前后端共提供 35 个 OpenAPI 路径、39 个接口操作。本文用于说明联调关系和业务
规则，不重复维护 Swagger 中已经存在的全部字段定义。

## 1. 服务边界

### 1.1 当前后端负责

- 采购申请、楼长审批、采购执行和仓库入库流程。
- 员工、角色、楼宇和当前处理人权限校验。
- 供应商主档、采购时供应商快照和黑名单。
- 历史品牌型号、相似采购和供应商推荐数据。
- 采购流程日志、经办人快照和各阶段时间。
- 外部 Agent 的会话、消息、短期状态和 MySQL 快照存储。
- 通知 Outbox、失败重试和人工补发。

### 1.2 当前后端不负责

- 大模型调用、提示词、意图识别、回复生成和工具编排。
- 飞书、钉钉、企业微信等平台登录态验证。
- 消息卡片或通知内容的最终渲染。
- 浏览器直接保存网关签名密钥。

外部 Agent 应通过 HTTP API 使用后端能力，不能直接读写 MySQL 或 Redis。

## 2. 基础地址与联调入口

本地默认地址：

```text
http://127.0.0.1:8000
```

## 3. 统一响应格式

### 3.1 成功响应

```json
{
  "success": true,
  "code": "OK",
  "message": "操作成功",
  "data": {},
  "trace_id": "9cc93e1b-0f4c-4eb5-8c72-dbc174d95c72"
}
```

### 3.2 失败响应

```json
{
  "success": false,
  "code": "CONCURRENT_MODIFICATION",
  "message": "采购申请版本已变化",
  "data": null,
  "trace_id": "9cc93e1b-0f4c-4eb5-8c72-dbc174d95c72"
}
```

调用方应：

1. 先根据 HTTP 状态码判断请求是否成功。
2. 使用 `code` 进行程序分支判断，不要依赖中文 `message`。
3. 面向用户显示业务化操作提示，不直接展示后端字段名或原始校验结构。
4. 记录 `trace_id`，用于后端排查同一次请求的日志。

## 4. 身份网关联调

### 4.1 调用链

```text
用户所在平台
  → 身份网关或平台适配层验证用户
  → 网关生成签名请求头
  → 采购后端验证签名和防重放
  → 根据平台身份解析员工、角色和楼宇
  → 执行业务接口
```

浏览器、外部 Agent 或普通业务客户端不得自行保存
`IDENTITY_GATEWAY_SECRET`。生产环境应由可信网关统一签名。

### 4.2 必需请求头

| 请求头 | 说明 |
| --- | --- |
| `X-Platform-Type` | 平台类型 |
| `X-Platform-User-Id` | 平台中的用户唯一标识 |
| `X-Gateway-Timestamp` | Unix 秒级时间戳 |
| `X-Gateway-Nonce` | 本次请求唯一随机数 |
| `X-Gateway-Signature` | HMAC-SHA256 十六进制签名 |

生产环境支持的平台类型：

- `FEISHU`
- `DINGTALK`
- `WECHAT_WORK`
- `WEB`

`TEST_PLATFORM` 只在非生产环境开放。

### 4.3 签名原文

按以下顺序使用换行符连接：

```text
HTTP_METHOD
URL_PATH
PLATFORM_TYPE
PLATFORM_USER_ID
TIMESTAMP
NONCE
```

示例：

```text
GET
/api/v1/requirements
FEISHU
ou_xxxxxxxxx
1785376200
Uj8Km2pL0zQn7dRs
```

使用 `IDENTITY_GATEWAY_SECRET` 对上述 UTF-8 文本执行 HMAC-SHA256，结果使用小写
十六进制字符串。

签名注意事项：

- HTTP 方法必须转为大写。
- 只签 URL 路径，不包含查询字符串。
- `X-Platform-Type` 参与签名前应使用大写。
- `nonce` 长度必须为 16 至 128，只能包含字母、数字、下划线和短横线。
- 默认签名有效期为 300 秒。
- 同一平台下的同一 `nonce` 在有效期内只能使用一次。
- 请求重试时必须重新生成时间戳、nonce 和签名。

### 4.4 Python 签名示例

```python
import hashlib
import hmac
import secrets
import time

method = "GET"
path = "/api/v1/requirements"
platform_type = "FEISHU"
platform_user_id = "ou_xxxxxxxxx"
timestamp = str(int(time.time()))
nonce = secrets.token_urlsafe(18)
secret = "从部署环境安全读取"

canonical = "\n".join(
    [method, path, platform_type, platform_user_id, timestamp, nonce]
)
signature = hmac.new(
    secret.encode("utf-8"),
    canonical.encode("utf-8"),
    hashlib.sha256,
).hexdigest()

headers = {
    "X-Platform-Type": platform_type,
    "X-Platform-User-Id": platform_user_id,
    "X-Gateway-Timestamp": timestamp,
    "X-Gateway-Nonce": nonce,
    "X-Gateway-Signature": signature,
}
```

### 4.5 当前用户

身份网关接通后，建议首先调用：

```http
GET /api/v1/users/me
```

该接口返回：

- 当前员工编号和姓名
- 平台身份
- 角色列表
- 可访问楼宇列表

前端或 Agent 不应自行声明当前员工编号、姓名、手机号、角色或楼宇权限。

## 5. 角色和采购状态

### 5.1 角色

| 角色代码 | 业务角色 |
| --- | --- |
| `APPLICANT` | 需求人 |
| `BUILDING_MANAGER` | 楼长 |
| `PURCHASER` | 采购员 |
| `WAREHOUSE_MANAGER` | 仓库管理员 |
| `ADMIN` | 系统管理员 |

一个员工可以拥有多个角色。后端会同时校验角色、楼宇、当前处理人和申请可见范围。

### 5.2 状态

```text
DRAFT
  → PENDING_REVIEW
  → REJECTED
  → PENDING_REVIEW
  → PENDING_PURCHASE
  → PURCHASING
  → PENDING_WAREHOUSE
  → COMPLETED
```

| 状态 | 含义 | 主要处理人 |
| --- | --- | --- |
| `DRAFT` | 草稿 | 需求人 |
| `PENDING_REVIEW` | 待楼长审批 | 楼长 |
| `REJECTED` | 楼长已驳回 | 需求人 |
| `PENDING_PURCHASE` | 待采购 | 采购员 |
| `PURCHASING` | 采购处理中 | 采购员 |
| `PENDING_WAREHOUSE` | 待入库 | 仓管 |
| `COMPLETED` | 已完成 | 无当前处理人 |

调用方不要自行修改状态，只能调用对应的流转接口。

## 6. 并发、幂等和重试

### 6.1 `expected_version`

保存字段和状态流转都要求提交当前申请的 `expected_version`。

调用要求：

1. 先从详情或上一次操作响应读取 `version`。
2. 把该值作为下一次操作的 `expected_version`。
3. 每次成功保存或流转后，用响应中的新 `version` 更新本地状态。
4. 收到 `CONCURRENT_MODIFICATION` 时重新查询详情，不要自动覆盖。

### 6.2 `action_token`

关键流转、黑名单操作和通知补发要求 `action_token`：

- 长度 8 至 64。
- 同一次业务动作的网络重试使用同一个 token。
- 新的业务动作必须生成新的 token。
- 推荐使用 UUID。

如果客户端超时但不确定后端是否成功，应使用同一 `action_token` 重试。后端返回
`DUPLICATE_OPERATION` 时，调用方应重新查询当前状态确认结果。

## 7. 采购主流程联调顺序

### 7.1 需求人

1. 创建草稿：

   ```http
   POST /api/v1/requirements
   ```

   ```json
   {
     "building_id": 1
   }
   ```

2. 保存需求字段：

   ```http
   PATCH /api/v1/requirements/{requirement_id}/applicant-fields
   ```

   草稿允许字段未填写完整。响应中的 `missing_fields` 和 `fields_complete` 可用于
   判断是否允许提示用户提交。

3. 查询可选楼长：

   ```http
   GET /api/v1/requirements/{requirement_id}/handler-candidates?target_role=BUILDING_MANAGER
   ```

4. 提交楼长审核：

   ```http
   POST /api/v1/requirements/{requirement_id}/submit-review
   ```

   ```json
   {
     "expected_version": 1,
     "assigned_to_employee_id": 1002,
     "action_token": "6ea4ee40-5474-44ef-a95b-2798cb897217"
   }
   ```

提交前需求人必填：

- `device_profession`
- `device_name`
- `quantity`
- `unit`
- `application_reason`

设备类型合法值：

- 电气
- 暖通
- 弱电
- 机房环境
- 工器具
- 算力服务器
- IDC网络
- 其他

### 7.2 楼长

1. 查询待办：

   ```http
   GET /api/v1/requirements?view=PENDING_FOR_ME
   ```

2. 查询申请详情：

   ```http
   GET /api/v1/requirements/{requirement_id}
   ```

3. 如需修改需求资料，调用需求字段保存接口。
4. 保存楼长审核资料：

   ```http
   PATCH /api/v1/requirements/{requirement_id}/review-fields
   ```

5. 驳回：

   ```http
   POST /api/v1/requirements/{requirement_id}/reject
   ```

   ```json
   {
     "expected_version": 3,
     "action_token": "8dc724e1-76b0-4a2e-b1df-512cad2859c2",
     "reason": "请补充采购用途说明"
   }
   ```

6. 审批通过前查询采购员：

   ```http
   GET /api/v1/requirements/{requirement_id}/handler-candidates?target_role=PURCHASER
   ```

7. 审批通过并提交采购员：

   ```http
   POST /api/v1/requirements/{requirement_id}/submit-purchaser
   ```

被驳回后，需求人使用以下接口重新提交：

```http
POST /api/v1/requirements/{requirement_id}/resubmit-review
```

### 7.3 采购员

1. 查询待采购：

   ```http
   GET /api/v1/requirements?view=PENDING_FOR_ME
   ```

2. 开始采购：

   ```http
   POST /api/v1/requirements/{requirement_id}/start-purchase
   ```

3. 搜索或新增供应商。
4. 保存采购执行资料：

   ```http
   PATCH /api/v1/requirements/{requirement_id}/purchase-fields
   ```

   `purchased_at` 建议提交带时区的 ISO 8601 时间，例如：

   ```text
   2026-07-30T14:31:00+08:00
   ```

5. 查询仓管候选：

   ```http
   GET /api/v1/requirements/{requirement_id}/handler-candidates?target_role=WAREHOUSE_MANAGER
   ```

6. 提交仓库：

   ```http
   POST /api/v1/requirements/{requirement_id}/submit-warehouse
   ```

采购快照规则：

- 每次采购始终保存本次供应商资料快照。
- `update_supplier_profile=false` 时只保存快照，不修改供应商主档。
- 只有采购员明确提交 `update_supplier_profile=true` 时才同步供应商主档。
- 实际总价必须等于申请数量乘以实际单价。

### 7.4 仓管

1. 查询待入库：

   ```http
   GET /api/v1/requirements?view=PENDING_FOR_ME
   ```

2. 保存入库资料：

   ```http
   PATCH /api/v1/requirements/{requirement_id}/warehouse-fields
   ```

3. 完成采购：

   ```http
   POST /api/v1/requirements/{requirement_id}/complete
   ```

实收数量可以少于、等于或多于申请数量。少于申请数量时必须在
`receipt_remark` 中填写说明。

## 8. 采购申请查询

### 8.1 角色工作台列表

```http
GET /api/v1/requirements
```

必需查询参数 `view`：

| `view` | 用途 |
| --- | --- |
| `CREATED_BY_ME` | 需求人查看自己发起的申请 |
| `PENDING_FOR_ME` | 当前角色查看待自己处理的申请 |
| `PROCESSED_BY_ME` | 查看本人已经处理过的记录 |
| `BUILDING_SCOPE` | 楼长查看管辖楼宇全部申请 |

可选参数：

- `status`
- `page`
- `page_size`

### 8.2 详情

```http
GET /api/v1/requirements/{requirement_id}
```

主要返回：

- 当前状态和版本
- 楼宇及当前处理人
- 需求字段
- 审批记录
- 采购执行快照
- 入库记录
- 缺失字段
- 当前身份允许执行的操作 `allowed_actions`

后端会根据角色对银行账号等敏感字段进行脱敏。前端应根据业务角色决定具体展示
区域，但不能依赖前端隐藏代替后端权限校验。

### 8.3 历史采购

```http
GET /api/v1/purchase-records
```

可按以下条件筛选：

- `requirement_no`
- `supplier_id`
- `status`
- `device_name`
- `brand`
- `model`
- `created_from`
- `created_to`
- `page`
- `page_size`

记录中包含创建、提交、审批、采购、入库和完成时间。未发生的阶段返回 `null`。

## 9. 流程履历和联系方式

查询流程履历：

```http
GET /api/v1/requirements/{requirement_id}/timeline
```

每个节点包含：

- `log_id`
- 操作类型
- 操作前后状态
- 经办人姓名和角色
- 经办人脱敏手机号
- 下一处理人及脱敏手机号
- 操作说明
- 操作时间

手机号默认脱敏。用户点击后，客户端按单条流程节点请求完整号码：

```http
GET /api/v1/requirements/{requirement_id}/timeline/{log_id}/contact?subject=operator
```

`subject`：

- `operator`：查看该节点操作人
- `assignee`：查看该节点下一处理人

只有原本有权查看该采购申请的用户才能调用。所有业务角色在有申请查看权限时都可
查看完整手机号；无申请权限的用户仍返回 `403`。

客户端不得在列表加载时批量获取完整手机号，应保持默认脱敏，仅在用户点击时调用。

## 10. 供应商和推荐接口

### 10.1 供应商

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/suppliers?keyword=...` | 按名称或统一社会信用代码搜索 |
| GET | `/api/v1/suppliers/{supplier_id}` | 查询主档和黑名单摘要 |
| POST | `/api/v1/suppliers` | 采购员或管理员新增供应商 |
| POST | `/api/v1/suppliers/{supplier_id}/blacklist` | 楼长登记黑名单 |
| POST | `/api/v1/suppliers/{supplier_id}/blacklists/{blacklist_id}/release` | 原登记楼长或管理员解除 |

黑名单时长：

- `PERMANENT`：永久，不能填写 `end_at`
- `LIMITED`：限时，必须填写 `end_at`

黑名单登记必须关联一条已经完成且实际使用该供应商的采购记录。

### 10.2 推荐

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/recommendations/products` | 推荐历史品牌型号 |
| GET | `/api/v1/recommendations/purchase-history` | 查询相似采购 |
| GET | `/api/v1/recommendations/suppliers` | 推荐历史供应商 |

推荐结果只使用有效业务数据。当前有效黑名单供应商不会进入供应商推荐。

## 11. 外部 Agent 联调

### 11.1 推荐调用顺序

```text
1. 获取或创建活动会话
2. 写入用户消息
3. 读取 Redis 会话状态
4. Agent 完成意图识别和字段收集
5. 更新会话状态
6. 按需调用采购、供应商或推荐接口
7. 写入 Agent 回复消息
8. 关键节点保存 MySQL 快照
9. 业务结束后完成会话
```

### 11.2 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/v1/agent/conversations/active` | 获取或创建当前动作的活动会话 |
| POST | `/api/v1/agent/conversations/{id}/messages` | 幂等写入消息 |
| GET | `/api/v1/agent/conversations/{id}/messages` | 分页读取消息 |
| GET | `/api/v1/agent/conversations/{id}/state` | 读取短期状态 |
| PUT | `/api/v1/agent/conversations/{id}/state` | 更新短期状态 |
| POST | `/api/v1/agent/conversations/{id}/snapshot` | 保存 MySQL 状态快照 |
| POST | `/api/v1/agent/conversations/{id}/complete` | 完成会话并清理 Redis 状态 |

### 11.3 会话约定

- `current_action` 由 Agent 定义当前正在办理的业务动作。
- `external_conversation_id` 对应外部平台会话标识。
- `external_message_id` 用于同一会话内的消息幂等。
- `sender_type` 只能是 `USER`、`AGENT` 或 `SYSTEM`。
- Redis 状态默认保留 72 小时。
- Redis 状态丢失时，后端会从最近的 MySQL 快照恢复关键状态。
- 完整消息保存在 MySQL。
- 不保存或返回模型内部思维过程。

短期状态可以保存：

- 已关联采购申请
- 当前动作
- 已收集字段
- 缺失字段和当前待询问字段
- 是否等待用户确认
- 最近消息
- 最近推荐结果

## 12. 通知网关联调

采购业务事务只写通知 Outbox，不直接调用飞书 SDK。后台 Worker 再调用平台无关的
HTTP 通知网关。

### 12.1 后端管理接口

| 方法 | 路径 | 权限和用途 |
| --- | --- | --- |
| GET | `/api/v1/notifications` | 管理员查询通知 |
| POST | `/api/v1/notifications/dispatch-due` | 管理员触发一批到期通知 |
| POST | `/api/v1/notifications/{notification_id}/resend` | 管理员人工补发失败通知 |

单次执行后台任务：

```powershell
python -m app.workers.notifications
```

### 12.2 后端调用通知网关

配置：

- `NOTIFICATION_GATEWAY_URL`
- `NOTIFICATION_GATEWAY_TOKEN`
- `NOTIFICATION_REQUEST_TIMEOUT_SECONDS`
- `NOTIFICATION_MAX_RETRIES`
- `NOTIFICATION_RETRY_BASE_SECONDS`
- `NOTIFICATION_RETRY_MAX_SECONDS`

请求头：

- `Authorization: Bearer <token>`，仅配置令牌时发送
- `Idempotency-Key: <notification.dedup_key>`
- `X-Notification-Id: <notification_id>`

请求体示例：

```json
{
  "notification_id": 1001,
```

## 13. 时间和敏感数据约定

### 13.1 时间

- 业务时间按北京时间保存和展示。
- 客户端提交时间时建议使用带 `+08:00` 的 ISO 8601 格式。
- 当前接口返回的无时区时间字符串应按北京时间解释。
- 不要把北京时间再次当作 UTC 增加 8 小时。

### 13.2 手机号

- 默认响应脱敏。
- 流程履历中的完整手机号只能通过点击后的单条联系接口获取。
- 调用完整号码接口仍受申请可见范围约束。

### 13.3 银行账号

- 后端按角色返回完整或脱敏银行账号。
- 采购员和管理员可以查看业务需要的完整资料。
- 其他角色不能依赖修改请求参数绕过脱敏。

## 14. 常见错误码和客户端处理

| HTTP | `code` | 含义 | 建议处理 |
| --- | --- | --- | --- |
| 401 | `IDENTITY_REQUIRED` | 缺少身份头 | 检查网关 |
| 400 | `INVALID_HANDLER` | 下一处理人不合法 | 重新查询候选人 |
| 400 | `MISSING_REQUIRED_FIELDS` | 尚未保存必填资料 | 引导用户先保存 |
| 401 | `INVALID_IDENTITY_SIGNATURE` | 签名错误 | 检查签名原文和密钥 |
| 401 | `IDENTITY_SIGNATURE_EXPIRED` | 签名过期 | 生成新时间戳和签名 |
| 401 | `IDENTITY_REPLAYED` | nonce 已使用 | 生成新 nonce 和签名 |
| 403 | `PERMISSION_DENIED` | 角色或数据权限不足 | 禁止操作，不要自动重试 |
| 403 | `BUILDING_NOT_ALLOWED` | 无楼宇权限 | 检查人员楼宇关系 |
| 404 | `REQUIREMENT_NOT_FOUND` | 采购申请不存在 | 返回列表并刷新 |
| 404 | `SUPPLIER_NOT_FOUND` | 供应商不存在或停用 | 重新搜索供应商 |
| 409 | `CONCURRENT_MODIFICATION` | 版本冲突 | 重新查询详情 |
| 409 | `INVALID_STATUS` | 当前状态不允许操作 | 刷新流程状态 |
| 409 | `DUPLICATE_OPERATION` | 幂等动作已执行 | 查询业务最终状态 |
| 422 | `VALIDATION_ERROR` | 参数或业务校验失败 | 修正输入后重试 |
| 500 | `INTERNAL_ERROR` | 未处理异常 | 记录 `trace_id` 后联系后端 |
| 503 | `IDENTITY_SERVICE_UNAVAILABLE` | Redis 身份防重放不可用 | 稍后重试 |

FastAPI 参数校验失败时，详细字段错误位于：

```text
data.errors
```

该结构供开发调试使用，前端应转换为用户能理解的操作提示。

## 16. 联调验收清单

### 身份网关

- 能生成五个必需身份头。
- 签名不包含查询字符串。
- 每次请求使用新 nonce。
- 未绑定员工、停用员工和过期签名能够正确处理。

### 前端或业务客户端

- 根据 `/users/me` 使用后端返回的角色和楼宇。
- 保存或流转后及时更新 `version`。
- 正确处理 `409` 并重新拉取详情。
- 手机号默认脱敏，只在点击时获取完整号码。
- 不把后端字段名直接展示给用户。
- 时间按北京时间解释。

### 外部 Agent

- 不直接访问数据库。
- 消息使用 `external_message_id` 幂等。
- Redis 状态丢失后可以从快照继续。
- Agent 调用业务接口时遵守状态机和 `expected_version`。
- 不把模型内部思维过程写入消息或状态。

### 通知网关

- 按 `Idempotency-Key` 去重。
- 正确处理后端重试。
- 返回 `2xx` 表示成功，非 `2xx` 表示失败。
- 不在日志中输出鉴权令牌。

## 17. 外部团队需要提供的信息

### 身份网关或平台适配层

- 实际 `platform_type`
- 平台用户唯一标识格式
- 员工与平台身份同步方式
- 请求来源网络和部署地址

### 外部 Agent

- Agent 服务部署地址
- 使用的 `current_action` 枚举
- 外部会话和消息 ID 生成规则
- Agent 需要调用的采购操作范围

### 通知网关

- 网关 URL
- 鉴权方式和令牌交付方式
- 错误响应格式
- 各 `event_type` 的最终消息模板或卡片格式

真实密钥、密码和令牌只能配置在部署环境，不得写入代码、文档、日志或 Git。
