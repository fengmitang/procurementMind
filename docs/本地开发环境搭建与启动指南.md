# Procurement Agent 本地启动指南

本文说明从拉取代码到启动服务所需的最低环境和操作步骤。

## 1. 最低环境要求

只需要安装：

| 软件 | 要求 | 用途 |
| --- | --- | --- |
| Git | 可正常执行 `git clone` | 拉取项目代码 |
| Python | `3.12.x` | 运行后端服务 |
| Docker | Docker Engine 或 Docker Desktop | 运行 MySQL 和 Redis |
| Docker Compose | Compose V2，可执行 `docker compose` | 管理项目容器 |

不要求使用 Conda，也不要求创建指定名称的虚拟环境。

建议使用任意 Python 虚拟环境工具隔离依赖，例如 Python 自带的 `venv`、Conda、
uv 或 Poetry，但这不是项目启动的硬性条件。

前端由 FastAPI 直接提供，不需要安装 Node.js 或 npm。

## 2. 项目运行组件

启动后会运行：

| 组件 | 地址 |
| --- | --- |
| FastAPI 后端 | `http://127.0.0.1:8000` |
| Swagger 接口文档 | `http://127.0.0.1:8000/docs` |
| 本地体验页面 | `http://127.0.0.1:8000/demo/` |
| MySQL | `127.0.0.1:3307` |
| Redis | `127.0.0.1:6380` |

MySQL 和 Redis 使用本项目独立的 Docker 容器、网络和数据卷，不复用本机已有
MySQL、Redis 或其他 Docker 项目的资源。

## 3. 拉取代码

```powershell
git clone https://github.com/fengmitang/Procurement-Agent.git
cd Procurement-Agent
```

后续命令都在项目根目录执行。

## 4. 准备 Python

确认 Python 版本：

```powershell
python --version
```

版本必须是 Python `3.12.x`。

### 可选：创建虚拟环境

如果希望隔离项目依赖，可以使用 Python 自带的 `venv`：

```powershell
python -m venv .venv
```

Windows PowerShell 激活方式：

```powershell
.\.venv\Scripts\Activate.ps1
```

Linux 或 macOS 激活方式：

```bash
source .venv/bin/activate
```

也可以使用其他虚拟环境工具。项目不依赖虚拟环境的名称。

## 5. 安装项目依赖

只启动服务：

```powershell
python -m pip install -e .
```

如果还需要运行测试和代码检查：

```powershell
python -m pip install -e ".[dev]"
```

安装命令会根据 `pyproject.toml` 自动安装 FastAPI、Uvicorn、SQLAlchemy、
Alembic、MySQL 异步驱动、Redis 客户端等依赖，无需逐个安装。

## 6. 生成本地配置

执行：

```powershell
python scripts/bootstrap_env.py
```

该脚本会创建 `.env.docker`，并自动生成本地 MySQL、Redis 和身份签名所需的随机
密码或密钥。密钥不会显示在终端中。

确认文件已生成：

```powershell
Test-Path .env.docker
```

`.env.docker` 只保存在本机，已被 Git 忽略，不要提交或发送给其他人。

## 7. 启动 MySQL 和 Redis

先确认 Docker 服务已经启动：

```powershell
docker version
docker compose version
```

启动项目容器：

```powershell
docker compose --env-file .env.docker up -d
```

查看状态：

```powershell
docker compose --env-file .env.docker ps
```

等待以下两个容器都变为 `healthy`：

- `procurement-agent-mysql`
- `procurement-agent-redis`

第一次启动时需要下载镜像并初始化 MySQL，可能需要等待几分钟。

## 8. 创建数据库表

Docker 会创建空数据库，但不会自动创建业务表。执行：

```powershell
python -m alembic upgrade head
```

检查迁移状态：

```powershell
python -m alembic current
```

输出应显示当前版本位于 `head`。

## 9. 可选：写入体验数据

如果需要在体验页面测试完整采购流程，执行：

```powershell
python scripts/seed_demo_data.py
```

成功时会输出：

```text
TEST demo data created and validated.
```

如果只需要空数据库，可以跳过此步骤。

注意：重复运行该脚本会重置 TEST 数据，也会清理使用体验页面 TEST 账号创建的
临时申请。

## 10. 启动后端

开发模式：

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

看到以下内容表示启动成功：

```text
Application startup complete.
Uvicorn running on http://127.0.0.1:8000
```

运行服务的终端需要保持打开。停止服务时按 `Ctrl + C`。

## 11. 验证启动结果

浏览器打开：

- 健康检查：`http://127.0.0.1:8000/health`
- 依赖检查：`http://127.0.0.1:8000/ready`
- 接口文档：`http://127.0.0.1:8000/docs`
- 体验页面：`http://127.0.0.1:8000/demo/`

`/ready` 正常时应显示：

- 服务状态为 `ready`
- MySQL 状态为 `ok`
- Redis 状态为 `ok`

如果 `/health` 正常但 `/ready` 不正常，说明后端已经启动，但 MySQL 或 Redis
没有连接成功。

## 12. 完整的首次启动命令

```powershell
git clone https://github.com/fengmitang/Procurement-Agent.git
cd Procurement-Agent

python -m pip install -e .
python scripts/bootstrap_env.py

docker compose --env-file .env.docker up -d
docker compose --env-file .env.docker ps

python -m alembic upgrade head

# 可选：生成体验数据
python scripts/seed_demo_data.py

python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

## 13. 以后再次启动

环境已经准备完成后，通常只需要：

```powershell
cd Procurement-Agent
docker compose --env-file .env.docker up -d
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

拉取新代码后建议执行：

```powershell
git pull
python -m pip install -e .
python -m alembic upgrade head
```

## 14. 停止服务

在 Uvicorn 终端按 `Ctrl + C`。

停止 MySQL 和 Redis：

```powershell
docker compose --env-file .env.docker down
```

普通 `down` 不会删除数据库和 Redis 数据。

不要在日常开发中执行：

```powershell
docker compose --env-file .env.docker down -v
```

`-v` 会删除本项目的 MySQL 和 Redis 数据卷。

## 15. 可选配置

通知网关等应用配置可以写入项目根目录的 `.env`：

```dotenv
NOTIFICATION_GATEWAY_URL=https://your-gateway.example/api/notify
NOTIFICATION_GATEWAY_TOKEN=replace_with_real_token
```

`.env` 和 `.env.docker` 都不能提交到 Git。

如果不配置通知网关，采购主流程仍可运行；通知发送会记录为失败，不会影响采购
事务提交。

## 16. 可选：运行测试

先安装开发依赖：

```powershell
python -m pip install -e ".[dev]"
```

然后执行：

```powershell
python -m pytest
python -m ruff check .
python -m ruff format --check .
```

注意：当前测试会重建本地 TEST 数据。运行测试前，确认不需要保留体验页面中使用
TEST 账号创建的临时申请。

## 17. 常见问题

### Python 版本不正确

项目要求 Python `3.12.x`。如果电脑中安装了多个 Python，请使用实际指向
Python 3.12 的命令运行本项目。

### Docker 无法连接

执行：

```powershell
docker version
```

必须同时显示 Client 和 Server 信息。如果只有 Client 信息，需要先启动 Docker
Desktop 或 Docker Engine。

### MySQL 或 Redis 未就绪

查看容器状态和日志：

```powershell
docker compose --env-file .env.docker ps
docker compose --env-file .env.docker logs --tail 100
```

确认本机端口 `3307` 和 `6380` 没有被其他程序占用。

### 端口 8000 被占用

Windows 可以执行：

```powershell
netstat -ano | Select-String ':8000'
```

停止已有服务后重新启动。

### 提示数据库表不存在

执行：

```powershell
python -m alembic upgrade head
```

### 页面没有体验数据

执行：

```powershell
python scripts/seed_demo_data.py
```

该命令会重置现有 TEST 数据。

### Git 在 Windows 上连接 GitHub 失败

在项目目录执行：

```powershell
git config http.sslBackend schannel
```

然后重新执行 `git pull`。
