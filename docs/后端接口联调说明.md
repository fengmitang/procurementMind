# ProcurementMind 后端与 Agent 接口联调说明

> 版本：V2.0
> 更新日期：2026-08-14

字段级契约、必填项和响应 Schema 以运行中服务的 `/openapi.json` 为准。本文件只维护服务边界、认证方式、典型调用链和关键业务约束，不手工固定路径/接口总数。

## 1. 服务边界

### 1.1 Procurement Backend（8000）

负责：

- 平台身份签名校验、员工/角色/楼宇权限。
- 采购申请、审批、采购、入库、供应商、推荐、通知和管理员业务。
- MySQL 事务、Redis 会话缓存、状态机、并发版本和幂等。
- Agent 会话、消息、状态和快照持久化。
- Analytics、Risk Signals、Similar Cases、Supplier Performance。
- 开发环境 React BFF：业务 Proxy、Agent SSE 与 HITL 转发。

### 1.2 Agent Service（8100）

负责：

- LangGraph 路由和编排。
- Model Runtime、RAG、Planner/Executor、Review、Trace。
- MCP 只读工具调用。
- SSE Agent 输出和 HITL 待确认动作。

Agent 不直接修改采购数据库；MCP 不直接访问 MySQL。采购事实、权限和写操作均以 Backend 为准。

### 1.3 React Web（5173 开发态）

浏览器只调用 Backend `/demo-api/*` BFF，不保存 `IDENTITY_GATEWAY_SECRET`，也不直接签名访问正式业务 API。生产身份层尚需部署适配。

## 2. 地址与契约入口

| 服务 | 基础地址 | OpenAPI |
|---|---|---|
| Backend | `http://127.0.0.1:8000` | `/openapi.json`、`/docs` |
| Agent | `http://127.0.0.1:8100` | `/openapi.json`、`/docs` |
| React | `http://127.0.0.1:5173/demo/` | 不适用 |

健康检查：Backend `/health`、`/ready`；Agent `/health`、`/ready`。

## 3. 统一响应

Backend 与 Agent 的普通 JSON 响应均使用统一 envelope，包含成功标记、业务码、消息、数据和 Trace/Request ID。错误处理必须以 HTTP 状态与业务 `code` 联合判断，不要只解析中文文本。

SSE 例外：`POST /api/v1/chat/stream` 返回 `text/event-stream`，最终 `completed` 或 `error` 事件中包含完整结果。

## 4. 身份网关

Backend 正式业务 API 使用服务端 HMAC 网关身份。调用方提供平台类型、平台用户、时间戳、Nonce 和签名；签名必须覆盖当前请求约定的原文。准确 Header 和算法以 `app/core/gateway_auth.py`、`app/api/dependencies.py` 和 OpenAPI 为准。

关键规则：

- Secret 只存在于服务端。
- Agent Backend Client 根据可信 `BackendIdentity` 生成签名。
- MCP 子进程身份与 Trace 由 Agent Runtime 通过环境注入，模型不能传入。
- 开发 BFF 只允许白名单 `TEST_PLATFORM` 测试用户。
- Nonce 与签名存在有效期，重放请求会被拒绝。

联调首先调用：

```http
GET /api/v1/users/me
```

它返回当前员工、角色、楼宇范围和权限上下文；前端菜单和业务访问必须以此为准。

## 5. 采购流程与写入约束

典型状态链路：

```text
需求人创建/保存草稿 → 提交
→ 楼长审批通过或驳回
→ 采购员选择供应商并登记采购
→ 提交仓库
→ 仓管记录入库
→ 完成采购
```

写接口共同约束：

- `expected_version`：乐观并发控制，版本不一致时客户端必须刷新。
- `action_token`：业务幂等键；重试时复用同一 token，不要生成新写入。
- 角色、楼宇、当前状态和必填字段由 Backend 重新校验。
- 数量、金额、供应商和状态字段使用 OpenAPI 当前 Schema，不按旧文档猜测。
- Agent 生成的草稿或建议不能当作已写入结果。

## 6. Backend 主要能力

### 6.1 采购申请

当前包含创建、修改草稿、分页列表、详情、提交、审批、采购登记、供应商选择、提交仓库、入库与完成等接口。不同角色使用相同业务 API，由 Backend 根据身份和状态裁剪可见数据与允许动作。

列表支持 `CREATED_BY_ME`、`PENDING_FOR_ME`、`PROCESSED_BY_ME`、`BUILDING_SCOPE`、`ADMIN_SCOPE` 等视图；实际枚举以 OpenAPI 为准。

### 6.2 记录与通知

- 采购历史和时间线。
- 当前处理人/联系人（敏感字段按权限脱敏）。
- 通知 Outbox 列表、重试和死信处理。
- Agent Conversation、Message、State、Snapshot。

### 6.3 供应商与推荐

- 供应商默认分页与关键词搜索。
- 供应商详情、创建、黑名单加入/移除。
- 楼宇范围供应商风险查询。
- 产品、历史价格和供应商推荐。

供应商选择器应发送稳定业务 ID，但 UI 必须让用户按名称搜索，不能要求手工输入数据库 ID。

### 6.4 Analytics Query

```http
POST /api/v1/analytics/purchase-query
```

只接受受控查询 DSL，支持有限过滤、分组、聚合、排序和分页。Backend 应用角色/楼宇权限、默认时间范围、扫描上限和查询超时；不接受 SQL。

### 6.5 Risk Signals

```http
GET /api/v1/requirements/{requirement_id}/risk-signals
```

返回确定性风险事实、规则阈值、关联记录与证据，不由模型重新计算权限或金额。

### 6.6 Similar Cases

```http
GET /api/v1/requirements/{requirement_id}/similar-cases?limit=10
```

返回基于可解释规则的相似采购案例。申请可见性仍按当前用户权限处理。

### 6.7 Supplier Performance

```http
GET /api/v1/suppliers/{supplier_id}/performance
```

可带起止日期，返回履约指标及分子/分母，避免只返回无法解释的比例。

### 6.8 Admin

前缀：

```text
/api/v1/admin
```

当前包含：

- `overview`：管理员真实概览。
- `references`：角色、楼宇等员工维护参考数据。
- `employees`：分页、创建、详情、修改和停用。
- 采购清单与供应商全局只读访问通过现有列表 API 的 Admin Scope 实现。

Admin 员工变更记录操作日志；当前身份仍来自平台身份/HMAC，并未实现本地密码系统。

## 7. Agent API

### 7.1 普通对话

```http
POST http://127.0.0.1:8100/api/v1/chat
```

开发环境请求包含 `platform_type=TEST_PLATFORM`、测试用户、消息、可选外部会话/消息 ID 和可选 `ui_context`。生产环境不能继续信任浏览器直传身份。

响应可包含：

- `route`
- `reply`
- `knowledge_sources`
- `business_results`
- `analysis`
- `risk_investigation`
- `form_draft` / `form_missing_fields`
- `review`
- `pending_action`
- `execution` / `performance`

### 7.2 SSE

```http
POST http://127.0.0.1:8100/api/v1/chat/stream
Accept: text/event-stream
```

当前事件包含以下类别（具体字段以 Agent OpenAPI/实现为准）：

- `conversation_started`
- `thinking`
- `analyzing`
- 检索/工具/正文增量类状态事件
- `citation`
- `tool_summary`
- `confirmation_required`
- `completed`
- `error`

客户端要求：

- 按 SSE event/data 边界解析，不按任意网络 chunk 解析 JSON。
- 收到 `completed` 或 `error` 后关闭连接。
- 页面卸载或用户取消时中止请求。
- 重试应创建新的外部消息 ID，避免把失败流与旧消息混合。
- 处理中状态只作 UI 提示，最终业务结果以 `completed.data` 为准。

### 7.3 HITL

```http
POST /api/v1/chat/actions/confirm
POST /api/v1/chat/actions/cancel
```

请求绑定平台身份、conversation ID、action ID 和 confirmation token。Token 一次性且有 15 分钟有效期；过期、取消、重复或并发消费必须按业务错误处理。确认成功只表示 Agent 已通过受控 Backend API 尝试执行，客户端仍应读取返回的最终业务状态。

## 8. Backend → Agent BFF

开发 Web 使用：

```text
POST /demo-api/agent-chat
POST /demo-api/agent-chat/stream
POST /demo-api/agent-actions/{confirm|cancel}
POST /demo-api/proxy
```

BFF 职责：

- 限制测试用户和允许的 HTTP 方法/目标路径。
- 为普通 Backend API 构造服务端身份签名。
- 将 Agent 普通响应、SSE 和 HITL 结果转发给浏览器。
- 保持 Trace ID 和错误状态。

这些端点只在 `APP_ENV=development` 下可用，不应作为生产公开契约。

## 9. `ui_context` 与 Context Assistant

当前 `ui_context` 只允许：

```json
{
  "page_type": "REQUIREMENT_DETAIL",
  "requirement_id": 91003,
  "user_draft": {}
}
```

- `page_type` 和 `requirement_id` 用于定位页面语境。
- `user_draft` 是可选、非权威的用户输入草稿。
- 申请状态、处理人、价格、供应商和权限仍由 MCP Tool 回查。
- 模型输出只能预填当前表单，不能自动提交。

## 10. MCP 调用边界

Agent 内部使用单一 stdio MCP Server。MCP 是内部工具协议，不是浏览器或外部团队直接联调的 HTTP 服务。

安全要求：

- MCP Server 不访问 MySQL/Redis。
- Tool 只调用 Backend API。
- Platform Identity 和 Trace 来自可信进程环境。
- 业务权限由 Backend 再校验。
- Tool 错误保持结构化，不允许模型用知识库猜测缺失的实时事实。

## 11. 常见错误处理

| 类型 | 客户端处理 |
|---|---|
| 401 身份/签名 | 重新建立服务端身份上下文，不在浏览器重签 |
| 403 权限 | 展示业务化无权限提示，不重复请求 |
| 404 数据不可见/不存在 | 不向用户泄露对象是否存在 |
| 409 版本或幂等冲突 | 刷新详情；按原 action token 判断已执行结果 |
| 422 字段校验 | 映射到中文表单字段，不直出 snake_case/原始 body |
| 503/504 服务或模型超时 | 保留 Trace ID，允许用户缩小问题或稍后重试 |
| Agent SSE `error` | 结束 loading，展示业务错误和重试入口 |

## 12. 联调顺序

1. 检查 Backend `/ready` 与 Agent `/ready`。
2. 调用 `/api/v1/users/me` 确认身份、角色和楼宇。
3. 完成角色对应的只读列表/详情联调。
4. 按 OpenAPI Schema 完成采购写流程，验证 version/token。
5. 联调 Agent 普通对话，再联调 SSE。
6. 使用真实 `pending_action` 验证 confirm/cancel/expired/repeated。
7. 从采购详情页发送 `ui_context`，确认 Tool 重新查询事实。
8. 检查浏览器资源与网络请求中没有 Secret/API Key。

## 13. 契约维护

- Backend 字段级变更后，从当前应用导出 OpenAPI，不手工维护接口数量。
- Agent SSE/HITL 变更需同步 Agent OpenAPI、前端 Client 和测试。
- MCP Tool 变更需同步 catalog、Schema、权限测试和相应 baseline 新版本。
- 历史 `docs/baseline/openapi-*.json` 是阶段记录，不直接覆盖。
