# 一、文档目的

本文档用于明确项目需要开发的功能、模块边界、模块之间的关系，以及每个模块对应的主要技术。

项目不把所有采购流程都交给 Agent，而是在现有采购业务系统上增加一层智能能力，重点实现三条主线：

1. 采购知识与业务问答。
2. 采购复杂查询与分析。
3. 审批辅助与异常调查。

采购申请提交、审批流转、权限判断、金额计算、黑名单生效判断等确定性业务，继续由原有后端系统负责。

---

# 二、系统总体模块划分

整个项目分为六层：

```text
一、用户交互层
    ├─ 智能对话
    ├─ 复杂查询结果
    ├─ 审批风险摘要
    ├─ 人工确认
    └─ 执行过程查看

二、Agent 工作流层
    ├─ Router Agent
    ├─ Knowledge Agent
    ├─ Analysis Agent
    ├─ Review Agent
    └─ Human-in-the-loop 节点

三、智能能力层
    ├─ RAG 知识检索
    ├─ Planner / Executor
    ├─ Memory 与任务状态
    ├─ Skills
    └─ 结构化输出

四、工具接入层
    ├─ MCP Client
    ├─ 采购数据 MCP
    ├─ 产品数据 MCP
    ├─ 供应商数据 MCP
    └─ 统计分析 MCP

五、业务与数据层
    ├─ 原采购后端
    ├─ MySQL
    ├─ Redis
    ├─ 向量数据库
    └─ 采购知识文档

六、工程保障层
    ├─ 权限与安全
    ├─ Trace 与可观测性
    ├─ 自动评测
    ├─ 超时、重试、熔断与降级
    └─ Docker 部署
```

# 三、用户交互层

## 3.1 智能对话模块

### 功能

为用户提供统一的自然语言入口。

支持用户提出：

- 采购制度问题。
- 采购流程问题。
- 当前采购单业务问题。
- 跨多个条件的复杂查询。
- 多约束产品和供应商分析。
- 审批风险调查问题。
- 对上一轮结果的连续追问。

### 示例

- “服务器硬盘采购需要填写哪些字段？”
- “为什么这张申请现在不能提交？”
- “查一下过去半年一号楼和二号楼采购的服务器硬盘，排除黑名单供应商。”
- “这张采购单有没有价格或者供应商风险？”
- “把刚才结果里有延期记录的供应商排除掉。”

### 对应技术

- FastAPI。
- Web 智能协同页面，作为第一版主要入口。
- LangGraph 工作流入口。
- Redis 会话记忆。
- 流式输出。
- Pydantic 结构化消息。

### 第一版要求

- 通过网页版直接使用，不依赖飞书。
- 支持文本输入。
- 支持展示普通答案、表格结果、风险摘要和引用来源。
- 支持连续追问。
- 支持显示任务处理中、失败和部分成功状态。

---

## 3.2 复杂查询结果模块

### 功能

将 Agent 的复杂查询结果以清晰形式展示。

支持：

- 数据表格。
- 分组统计。
- 品牌对比。
- 价格区间。
- 供应商履约情况。
- 候选方案。
- 查询条件回显。
- 数据来源和统计口径。

### 对应技术

- 前端表格和卡片组件。
- Pydantic 结构化结果。
- 后端查询 DSL。
- MCP 工具返回结构化数据。

### 关键要求

- 结果页面必须显示本次查询使用的条件。
- 必须说明时间范围、楼宇范围和统计口径。
- 不能只返回一段自然语言总结。
- 数据不足时显示缺失项。

---

## 3.3 审批风险摘要模块

### 功能

在楼长或采购员查看待处理采购单时，展示 Agent 生成的风险摘要。

摘要包括：

- 重复采购风险。
- 价格异常。
- 数量异常。
- 供应商黑名单。
- 供应商延期。
- 相似历史采购。
- 相关制度依据。
- 需要人工核实的内容。

### 对应技术

- 后端固定风险规则。
- Analysis Agent。
- RAG。
- 多 MCP 工具调用。
- Review Agent。
- 结构化风险项。
- Human-in-the-loop。

### 关键要求

每条风险必须包含：

- 风险类型。
- 风险等级。
- 事实依据。
- 数据来源。
- 对应规则。
- 可能原因。
- 是否需要人工确认。

---

## 3.4 人工确认模块

### 功能

控制 Agent 不能直接完成的正式业务操作。

适用操作：

- 保存审批意见草稿。
- 保存采购分析报告。
- 写入审批备注。
- 修改采购草稿。
- 提交采购申请。
- 审批通过或驳回。

### 完整流程

```text
Agent 生成草稿
→ 前端展示
→ 用户修改或确认
→ 后端再次校验权限
→ 执行业务写入
→ 保存审计日志
```

### 对应技术

- LangGraph interrupt / resume。
- Checkpoint。
- 后端权限校验。
- 幂等令牌。
- 操作审计。

### 第一版范围

第一版至少支持：

- 审批意见草稿生成。
- 用户确认后保存到采购单备注。
- 拒绝或修改 Agent 草稿。

---

## 3.5 执行过程查看模块

### 功能

展示一次 Agent 请求的处理过程，方便调试、评测和项目演示。

展示内容：

- 用户问题。
- 路由结果。
- 查询计划。
- RAG 检索结果。
- MCP 工具调用。
- 中间结果。
- Review 结果。
- 最终答案。
- 每一步耗时。
- Token 和费用。

### 对应技术

- Trace ID。
- Langfuse，或 OpenTelemetry。
- 自定义 Trace 表。
- 前端时间线组件。

### 第一版要求

第一版可以先实现简单后台页面或日志页面，不要求复杂监控大屏。

---


## 3.6 Web 入口与平台适配模块

### 功能

第一版提供完整的 Web 使用入口，统一承载：

- 采购业务页面。
- Agent 对话。
- 复杂查询结果。
- 审批风险摘要。
- 人工确认。
- Trace 查看。

### 身份策略

#### P0 开发环境

- 复用现有 TEST 用户和角色切换。
- 使用真实后端权限和楼宇校验。
- 浏览器不保存后端身份签名密钥。

#### P1 正式 Web 环境

- 增加 Web 登录和服务端 Session。
- 由 BFF 或服务端身份网关生成后端签名。
- 普通采购请求发送给采购后端。
- 智能协同请求发送给 Agent 服务。

#### P2 可选平台适配

- 增加飞书应用和身份映射。
- 将飞书消息转换为统一 Agent 请求。
- 将结构化结果渲染为飞书卡片。
- 复用同一 Agent API，不复制 Agent 工作流。

### 对应技术

- HTML/CSS/JavaScript，第一版可复用现有页面。
- FastAPI 静态文件或独立前端服务。
- Session Cookie。
- BFF。
- 平台适配器模式。

### 第一版要求

- Web 端能够独立完成三条核心 Agent 演示链路。
- 飞书不作为第一版依赖或验收条件。

# 四、Agent 工作流层

## 4.1 Router Agent 模块

### 功能

判断用户问题应该进入哪一条工作流。

主要任务类型：

1. 知识问答。
2. 业务数据查询。
3. 混合问题。
4. 复杂查询与分析。
5. 审批风险调查。
6. 表单预填。
7. 复合任务。

### 复合任务示例

用户问：

> “先告诉我黑名单规则，再看看这个供应商是否适合当前采购。”

Router 需要拆成：

- 子任务一：查询黑名单制度。
- 子任务二：查询供应商实际业务数据。
- 子任务三：合并制度和实时数据。

### 输入

- 用户原始问题。
- 用户角色。
- 当前业务页面。
- 当前采购单编号。
- 会话上下文。

### 输出

- 任务类型。
- 子任务列表。
- 后续工作流。
- 需要的 Agent。
- 是否需要澄清。

### 对应技术

- LangGraph 路由节点。
- LLM 结构化输出。
- Pydantic Schema。
- 轻量模型。
- 路由评测集。

### 第一版要求

- 正确区分三条核心主线。
- 支持单任务和简单复合任务。
- 不负责生成最终业务答案。

---

## 4.2 Knowledge Agent 模块

### 功能

处理采购制度、流程、职责、字段要求和相关业务解释。

包括：

- 纯文档问答。
- 具体采购单业务解释。
- 文档规则与业务数据结合回答。

### 输入

- 用户问题。
- 用户角色。
- 采购单数据，可选。
- RAG 检索片段。
- Knowledge Skill。

### 输出

- 回答正文。
- 文档来源。
- 文档版本。
- 业务数据来源。
- 无法确认的部分。

### 对应技术

- RAG。
- 向量检索。
- 关键词检索。
- 混合检索。
- Rerank。
- Metadata 权限过滤。
- MCP 业务查询。
- 结构化引用。

### 第一版要求

至少支持：

- 设备采购字段要求。
- 角色职责。
- 黑名单规则。
- 采购流程。
- 当前申请不能提交原因。
- 下一处理人和当前状态解释。

---

## 4.3 Analysis Agent 模块

### 功能

统一负责：

- 自然语言复杂查询。
- 多约束候选方案分析。
- 审批异常补充调查。
- 跨数据源结果整合。

第一版不再继续拆成 Query Agent、Recommendation Agent 和 Risk Agent。

### 输入

- 用户目标。
- 提取后的查询条件。
- 当前任务记忆。
- 已有风险检查结果。
- 可用 MCP 工具。
- Analysis Skill。

### 输出

- 结构化查询计划。
- 工具调用步骤。
- 中间结果。
- 查询结果或候选方案。
- 风险摘要草稿。
- 证据列表。

### 对应技术

- LangGraph。
- Planner / Executor。
- MCP。
- Tool Calling。
- asyncio 并行调用。
- Redis 任务状态。
- 查询 DSL。
- Pydantic 结构化输出。

### 第一版要求

至少完成两个完整场景：

#### 场景 A：复杂组合查询

支持跨：

- 时间。
- 楼宇。
- 设备。
- 品牌。
- 供应商。
- 金额。
- 状态。
- 黑名单和延期条件。

#### 场景 B：审批风险调查

能够：

- 读取后端初步风险结果。
- 查询历史价格。
- 查询供应商风险。
- 查询相似案例。
- 检索制度。
- 生成风险摘要。

---

## 4.4 Review Agent 模块

### 功能

在答案返回前，检查初步结果是否可靠。

检查内容：

- 是否有事实来源。
- 是否遗漏用户条件。
- 是否引用错误文档。
- 是否编造产品、价格或供应商。
- 是否把推测写成事实。
- 是否越过审批边界。
- 是否缺少重要风险。
- 是否需要补查。

### 输入

- 用户问题。
- 路由结果。
- 查询计划。
- 工具调用结果。
- RAG 片段。
- 初步答案。

### 输出

- 审查通过。
- 需要补查。
- 需要重写。
- 删除无依据结论。
- 审查原因。

### 对应技术

- LLM 结构化审查。
- 程序规则校验。
- 证据映射。
- LangGraph 条件回路。
- Review Skill。

### 关键说明

Review Agent 不能代替程序完成精确校验。

例如：

- 数字是否正确，应由代码核对。
- 供应商是否在黑名单，应由工具结果确认。
- Review Agent 主要检查语义、遗漏、证据和越权。

---

## 4.5 Human-in-the-loop 工作流模块

### 功能

在写入或高风险决策前暂停工作流。

支持：

- Agent 生成草稿后暂停。
- 用户修改。
- 用户确认。
- 用户拒绝。
- 确认后继续执行。

### 对应技术

- LangGraph interrupt。
- Checkpoint。
- Redis。
- 幂等控制。
- 后端二次权限校验。

---

# 五、智能能力层

## 5.1 RAG 知识检索模块

### 功能

处理采购制度、流程、规则和历史案例检索。

### 子模块

#### 1. 文档导入

支持导入：

- Markdown。
- PDF。
- Word。
- 采购流程说明。
- 角色职责。
- 设备字段要求。
- 内部制度。
- 历史案例。

#### 2. 文档清洗与切分

- 按标题、条款和流程步骤切分。
- 保存原文位置。
- 过滤无关页眉页脚。
- 避免只按固定长度机械切分。

#### 3. Metadata 管理

保存：

- 文档名称。
- 类型。
- 版本。
- 生效时间。
- 适用角色。
- 适用设备。
- 权限范围。
- 是否过期。

#### 4. 检索

- 向量检索。
- 关键词检索。
- Metadata 过滤。
- 混合召回。
- Rerank。
- 去重。
- Top-K 结果。

#### 5. 引用

返回：

- 文档名称。
- 文档版本。
- 章节。
- 相关片段。
- 匹配得分。

### 对应技术

- LangChain Retriever。
- Chroma，第一版。
- Embedding 模型。
- BM25 或关键词搜索。
- Rerank 模型。
- 文档解析工具。
- RAGAS 或自定义评测。

### 第一版要求

先完成基础向量检索和引用，再增加混合检索与 Rerank。

---

## 5.2 Planner / Executor 模块

### 功能

将复杂问题拆成可执行步骤，并逐步调用工具。

### Planner 负责

- 提取目标。
- 整理已知条件。
- 发现缺失条件。
- 生成步骤。
- 指定工具。
- 判断步骤依赖。
- 设定终止条件。

### Executor 负责

- 执行计划。
- 保存工具结果。
- 处理失败。
- 根据结果调整下一步。
- 防止重复调用。
- 判断结果是否足够。

### 对应技术

- LangGraph State。
- LLM Structured Output。
- Tool Calling。
- Pydantic。
- 最大步骤限制。
- Token 和费用预算。

### 第一版要求

- 支持顺序执行。
- 支持可并行步骤。
- 支持一次计划调整。
- 支持最大工具调用次数和超时。

---

## 5.3 Memory 与任务状态模块

### 功能

保存连续对话和长任务状态。

### 会话记忆

保存：

- 当前时间范围。
- 当前楼宇。
- 当前设备。
- 当前品牌。
- 当前供应商。
- 已排除条件。
- 上一轮结果摘要。

### 任务状态

保存：

- 当前计划。
- 已完成步骤。
- 工具结果。
- 待执行步骤。
- Review 结果。
- 人工确认状态。
- 错误和重试次数。

### 对应技术

- Redis。
- LangGraph Checkpoint。
- MySQL 任务摘要，可选。
- TTL。
- 对话摘要压缩。

### 第一版要求

- 支持连续追问。
- 支持任务恢复。
- 支持任务结束后自动过期。
- 暂不做长期用户画像。

---

## 5.4 Skills 模块

### 功能

保存可以动态加载的业务规则和 Agent 行为约束。

### Skill 分类

- Knowledge Skill。
- Query Skill。
- Recommendation Skill。
- Risk Skill。
- Review Skill。

### 每个 Skill 包含

- 适用场景。
- 允许工具。
- 禁止行为。
- 输出要求。
- 安全边界。
- 失败处理。
- 示例。

### 对应技术

- Markdown / YAML Skill 文件。
- 动态加载。
- 版本记录。
- 缓存与热更新。
- Trace 中记录 Skill 版本。

### 第一版要求

- 按任务类型加载 Skill。
- 修改 Skill 后无需修改 Agent 核心代码。
- 不把权限控制只写在 Skill 中，权限仍由后端验证。

---

## 5.5 结构化输出模块

### 功能

统一 Agent 和工具之间的数据格式。

### 需要结构化的内容

- 路由结果。
- 子任务。
- 查询条件。
- 查询计划。
- 工具参数。
- 候选方案。
- 风险项。
- 证据来源。
- Review 结果。
- 最终报告。

### 对应技术

- Pydantic。
- LLM Structured Output。
- Function Calling。
- JSON Schema。
- 校验失败重试。

### 第一版要求

所有核心步骤不得只依赖自由文本传递。

---

# 六、MCP 与业务工具层

## 6.1 MCP Client 管理模块

### 功能

统一连接和调用各类 MCP Server。

负责：

- 工具发现。
- 工具 Schema 加载。
- 调用路由。
- 参数校验。
- 超时和重试。
- Trace ID 传递。
- 错误统一处理。
- 工具调用权限检查。

### 对应技术

- 标准 MCP Python SDK。
- MCP Client。
- Pydantic。
- asyncio。
- 熔断和重试组件。

---

## 6.2 采购数据 MCP Server

### 功能

向 Agent 提供采购业务数据。

工具范围：

- 查询采购申请详情。
- 查询历史采购。
- 查询采购状态。
- 查询当前处理人。
- 查询审核记录。

# 十四、核心演示流程

## 演示一：知识与业务混合问答

用户：

> 为什么这张服务器硬盘采购单不能提交？

系统：

1. Router 判断为混合问题。
2. Knowledge Agent 检索服务器硬盘字段要求。
3. 采购 MCP 查询当前采购单。
4. 对照缺失字段和制度。
5. Review Agent 检查来源。
6. 返回原因、缺失字段和制度引用。

---

## 演示二：自然语言复杂查询

用户：

> 查询过去半年一号楼和二号楼采购的服务器硬盘，排除黑名单供应商，只看单价超过 3000 元的，再比较品牌平均价格。

系统：

1. Router 判断为复杂查询。
2. Analysis Agent 生成结构化查询计划。
3. 采购 MCP 查询历史采购。
4. 供应商 MCP 查询黑名单。
5. 分析 MCP 计算品牌平均价格。
6. 返回表格、统计结果和查询条件。
7. 保存任务记忆。

用户继续：

> 再排除有延期记录的供应商。

系统保留上一轮条件，追加供应商延期过滤并重新生成结果。

---

## 演示三：审批风险调查

楼长打开采购单并点击“生成风险摘要”。

系统：

1. 后端检查重复申请、价格、数量和黑名单。
2. Analysis Agent 根据初步风险生成补查计划。
3. 并行查询历史价格、供应商履约和相似案例。
4. RAG 检索相关制度。
5. 生成风险摘要。
6. Review Agent 逐项核查证据。
7. 楼长查看摘要，并选择是否生成审批意见草稿。
8. 楼长确认后保存审批意见。
