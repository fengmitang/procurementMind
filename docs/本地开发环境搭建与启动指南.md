# ProcurementMind 本地开发环境搭建与启动指南

> 版本：V2.0
> 更新日期：2026-08-14
> 适用目录：`F:\Studio\ProcumentMind`

本指南以当前 `pyproject.toml`、`frontend/package.json`、`compose.yaml`、`.env.example` 和启动脚本为准。项目包含 MySQL、Redis、Qdrant、采购 Backend、独立 Agent Service 和 React Web。

## 3. 准备配置

项目使用两个本地环境文件：

- `.env`：本地 Python 进程读取。
- `.env.docker`：Compose 和 `scripts/start_dev.ps1` 使用。

二者都已被 `.gitignore` 忽略。首次准备时，以 `.env.example` 为字段参考，分别创建本地文件并替换示例密码：

```powershell
Copy-Item .env.example .env
Copy-Item .env.example .env.docker
```

至少必须提供：

```dotenv
MYSQL_PASSWORD=<本地强密码>
MYSQL_ROOT_PASSWORD=<本地强密码>
REDIS_PASSWORD=<本地强密码>
IDENTITY_GATEWAY_SECRET=<至少 16 字符的随机值>
```

不要把密码、API Key 或 `.env*` 内容写入文档、日志或提交。

### 3.1 生成模型

当前真实运行时使用 Provider-neutral Adapter，默认注册 `openai_compatible`：

```dotenv
MODEL_PROVIDER=openai_compatible
PRIMARY_MODEL=<主模型名>
FALLBACK_MODEL=<可选回退模型名>
MODEL_API_KEY=<模型 API Key>
MODEL_BASE_URL=<OpenAI-compatible Base URL>
```

模型配置为空时，确定性路由、工具和部分降级链路仍可测试；需要 Router、Query Rewrite、Planner、Compose、Review 的真实模型验收时必须完整配置。

### 3.2 RAG Provider

默认远程配置：

```dotenv
RAG_EMBEDDING_PROVIDER=aliyun_bailian
RAG_RERANK_PROVIDER=aliyun_bailian
RAG_EMBEDDING_MODEL=qwen3.7-text-embedding
RAG_RERANK_MODEL=qwen3-rerank
RAG_API_KEY=<可留空以复用 MODEL_API_KEY>
RAG_BAILIAN_BASE_URL=<可留空以复用 MODEL_BASE_URL>
QDRANT_COLLECTION=procurement_knowledge_child_qwen37
RAG_DENSE_VECTOR_SIZE=1024
```

可选本地 BGE：

```dotenv
RAG_EMBEDDING_PROVIDER=local_bge
RAG_RERANK_PROVIDER=local_bge
EMBEDDING_MODEL_PATH=F:/AIModels/bge-m3
RERANKER_MODEL_PATH=F:/AIModels/bge-reranker-v2-m3
RAG_MODEL_DEVICE=cpu
```

Embedding Provider、模型或向量维度变化后，设置新的 `QDRANT_COLLECTION` 并重新建索引。不要复用包含不同向量空间的 Collection。

## 5. 方式 A：Docker Compose

Compose 当前包含：

- `mysql`
- `redis`
- `qdrant`
- 一次性 `migrate`
- `backend`（8000）
- `agent`（8100）

启动：

```powershell
docker compose --env-file .env.docker up -d --build
docker compose --env-file .env.docker ps
```

查看日志：

```powershell
docker compose --env-file .env.docker logs --tail 100 backend agent migrate
```

停止并保留数据卷：

```powershell
docker compose --env-file .env.docker down
```

重要边界：当前 Compose 没有 frontend service，Dockerfile 也没有 Node 构建阶段；因此这条命令不会构建或启动 React Web。需要 Web 时在宿主机另启 Vite。Backend 的 `/demo` 静态挂载仅在镜像/工作区已经存在可用 `frontend/dist` 时才可能提供构建产物，而当前标准镜像构建不会生成该目录。

## 6. 方式 B：本地开发调试

### 6.1 推荐一键脚本

确保 `.env`、`.env.docker`、Python 环境和前端依赖已准备：

```powershell
.\scripts\start_dev.ps1
```

脚本实际执行：

1. 通过 Compose 启动 MySQL、Redis、Qdrant。
2. 等待三个容器健康。
3. 使用固定 Python 执行 `alembic upgrade head`。
4. 以 reload 模式启动 Backend 8000。
5. 以 reload 模式启动 Agent 8100。
6. 以 Vite 启动 React 5173。

日志写入 `.tmp/dev/logs/`。停止脚本只停止它自己启动的本地进程和三个基础设施容器，不删除数据卷：

```powershell
.\scripts\stop_dev.ps1
```

### 6.2 手工启动

启动基础设施：

```powershell
docker compose --env-file .env.docker up -d mysql redis qdrant
```

迁移：

```powershell
F:\Anaconda\envs\purchasing-agent\python.exe -m alembic upgrade head
```

分别在三个终端启动：

```powershell
# 终端 1：Backend
F:\Anaconda\envs\purchasing-agent\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload

# 终端 2：Agent
F:\Anaconda\envs\purchasing-agent\python.exe -m uvicorn agent_app.main:app --host 127.0.0.1 --port 8100 --reload

# 终端 3：React
Set-Location frontend
npm.cmd run dev
```

## 8. 健康与就绪检查

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/ready
Invoke-RestMethod http://127.0.0.1:8100/health
Invoke-RestMethod http://127.0.0.1:8100/ready
```

## 10. 常见问题

### Python 版本或环境错误

不要使用系统 Python。确认所有安装、迁移、脚本和测试都由：

```text
F:\Anaconda\envs\purchasing-agent\python.exe
```

执行。

### Vite 提示 Node 版本不支持

当前依赖要求 Node `^20.19.0`、`^22.12.0` 或 `>=24`。升级 Node 后重新安装前端依赖。

### `start_dev.ps1` 提示缺少 `.env.docker`

从 `.env.example` 复制并填写本地密码。不要直接使用示例密码。

### MySQL、Redis 或 Qdrant 不健康

```powershell
docker compose --env-file .env.docker ps
docker compose --env-file .env.docker logs --tail 100 mysql redis qdrant
```

检查宿主机端口 `13307`、`16380`、`6333` 是否占用，并确认 Docker Desktop 已启动。

### Agent `/ready` 失败

先检查 Backend `/ready`、模型 Provider 注册/初始化状态和 `IDENTITY_GATEWAY_SECRET`。Backend 与 Agent 必须使用相同的身份网关 Secret。Qdrant/RAG 故障通常在知识检索或索引脚本中暴露，不是 Agent `/ready` 的当前探测项。

### RAG 初始化失败

- 远程模式：检查 RAG 或模型 Key、Base URL、模型名和网络。
- 本地模式：检查两个模型目录及 `RAG_MODEL_DEVICE`。
- Collection Schema 不匹配：更换 Provider-specific Collection 并重建索引。

### React 页面能打开但请求失败

确认 Backend 8000 和 Agent 8100 均启动；Vite 会把 `/demo-api` 代理到 Backend，Backend 再通过 BFF 调用 Agent。

### Compose 启动后没有 React 页面

这是当前架构边界，不是容器健康故障。Compose 未包含 frontend service；在 `frontend/` 运行 `npm.cmd run dev`，访问 `http://127.0.0.1:5173/demo/`。

### 端口被占用

默认端口由 `.env.example`、Compose 和脚本共同约定。修改前先确认对应服务、Vite 代理和访问地址，避免只改一处。

### Git for Windows 访问远端失败

本项目仓库级配置可使用 Windows `schannel`。该设置与本地运行无关，本指南不要求访问远端。
